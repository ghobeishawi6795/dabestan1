# 📚 دبستان

سامانه هوشمند مدیریت و ارسال تکالیف دانش‌آموزان ابتدایی.

## 🎯 درباره پروژه

**دبستان** یک پلتفرم SaaS برای مدیریت تکالیف مدرسه است که سه نقش اصلی دارد:

- 👩‍🏫 **معلم**: ساخت تکلیف، ارسال به دانش‌آموزان، بررسی و بازخورد
- 🎒 **دانش‌آموز**: مشاهده تکالیف، انجام و ارسال پاسخ، دریافت بازخورد
- 🏫 **مدیر مدرسه**: نظارت کلی بر مدرسه، معلمان، کلاس‌ها و گزارش‌ها

## ✨ ویژگی‌ها

- 📱 طراحی Mobile-first
- 🎨 Design System یکپارچه
- ⚡ سریع و سبک (بدون فریم‌ورک)
- 🌐 کاملاً راست‌چین (RTL)
- 🎭 انیمیشن‌های نرم و حرفه‌ای
- 📎 پشتیبانی از چند نوع پاسخ (متن، عکس، صوت، فایل)

## 🚀 اجرا به صورت محلی

کافیست پوشه پروژه را باز کنید و `index.html` را در مرورگر باز کنید.

یا با یک سرور ساده:

```bash
# با Python
python -m http.server 8000

# با Node.js
npx serve
```

سپس به آدرس `http://localhost:8000` بروید.

## 🌐 دیپلوی روی Cloudflare Pages

1. این ریپازیتوری را به GitHub پوش کنید.
2. وارد [Cloudflare Dashboard](https://dash.cloudflare.com) شوید.
3. به بخش **Workers & Pages** بروید.
4. روی **Create** و سپس **Pages** کلیک کنید.
5. گزینه **Connect to Git** را انتخاب کنید.
6. ریپازیتوری `dabestan` را انتخاب کنید.
7. تنظیمات Build:
   - **Build command**: (خالی بگذارید)
   - **Build output directory**: `public`
8. روی **Save and Deploy** کلیک کنید.

### تنظیم دیتابیس (D1)

1. در همون پروژه‌ی Pages: **Settings → Functions → D1 database bindings**
2. یک D1 database بساز (یا از قبل ساخته شده رو انتخاب کن)، Variable name رو `DB` بذار.
3. اسکیمای `db/schema.sql` رو روی اون دیتابیس اجرا کن:
   ```bash
   wrangler d1 execute dabestan2 --file=db/schema.sql
   ```

### تنظیم کلید رمزنگاری توکن ورود

قبل از استفاده‌ی واقعی، حتماً یک secret تصادفی و طولانی برای امضای توکن‌های ورود تنظیم کن (وگرنه از یک مقدار پیش‌فرض توسعه استفاده می‌شه که امن نیست):

**Settings → Functions → Environment variables**، یک متغیر به اسم `AUTH_SECRET` با یک رشته‌ی طولانی و تصادفی اضافه کن (و به‌عنوان Secret علامت بزن، نه Plaintext).

## 🔐 نکات امنیتی این نسخه

- ورود همه‌ی نقش‌ها (مدیر/معلم/دانش‌آموز) از طریق کد دعوت + رمز عبور انجام می‌شود.
- رمزهای عبور با PBKDF2-SHA256 (نه base64) هش می‌شوند.
- بعد از ورود، یک توکن امضاشده (HMAC) صادر می‌شود و هر endpoint حساس، هویت کاربر را از روی همین توکن تایید می‌کند - نه از روی id ای که کلاینت در body می‌فرستد.
- عملیات ویرایش/حذف تکلیف، مالکیت (teacher_id) را هم چک می‌کند.
